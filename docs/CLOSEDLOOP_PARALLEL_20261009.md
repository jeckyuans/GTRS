# 闭环非必要串行的并行化

本轮从已验证并发布的词表缓存版本继续，模型、checkpoint、selector、FP32、合法输入、控制器和原图评分不变。

## 已实现

1. CPU图像/status预处理在现有RPC请求线程执行，不同会话可同时准备；唯一GPU模型线程从已准备的队列取batch。CPU准备与其他会话的GPU前向可重叠，没有跨单场景时序依赖。
2. 缓冲最多容纳两个batch的准备/排队/未完成请求；客户端超时后，该请求仍占容量直到GPU工作完成，避免超时重试形成无界缓冲。停止期间完成的准备被拒绝入队；异常仍返回失败。
3. 四卡各自执行configure→启动服务→等待本卡ready→启动runtime，移除所有卡配置完成的共同barrier。共享startup cancellation会保留最初错误并停止后续启动。

旧batch policy只有predict_batch时仍走原路径。GPU前向仍由原单模型worker执行；相机图像变换和拼接/stack数值方法未改变。

## 验证

- 双模型并行/重叠/错误/停止/超时容量10项CPU测试通过；卡级启动与错误取消2项通过。
- SparseDrive旧batch/真实输入预处理17项CPU回归通过。
- 8个固定真实RGB/ego帧，batch=1/2/4，每模型14组串行/准备后前向对照，全部检查输出逐位一致，checkpoint张量不变。
- 4并发会话、32调用、3次重复，串行/并行中位数：W0 4.1308→3.9424s（1.0478×），R1 4.2291→4.2157s（1.0032×），SparseDrive 3.0605→1.2921s（2.3687×）。这是policy流水线吞吐，不包括渲染/控制器/启动，不是整轮闭环倍率。

固定32场景、4×4、同checkpoint的完整对照已完成：SparseDrive串行270.913→并行234.062s（减少13.603%）；R1基线241.051→并行295.365s（增加22.532%）。得分、status/failure和碰撞/offroad/corridor硬事件逐场一致；原始子指标分别有1场4项和1场3项差异，未宣称全字段逐位一致或全SDK收益。所有显存余量与32核检查通过。

SparseDrive默认启用已测并行组合；GTRS默认继续使用此前缓存部署及原启动顺序，`--parallel-execution`只作为实验选项。W0只有推理流水线检查，没有本轮完整闭环对照。启动和CPU/GPU重叠是组合测试，不能把总耗时变化单独归因到某一项。
